# Backup Studio

高性能本地目录备份工具。面向「同一批文件反复备份」的真实场景：目标目录已存在旧备份时，靠内容哈希去重避免重复复制；源端文件改名或移动时，目标端同步路径变化，而不是复制出第二份。

界面遵循 [desktop-agent-ui](https://github.com/Ludi-Herry/desktop-agent-ui) 设计规范：去边框分层、发丝描边、同心圆角、阻尼弹簧动效、暗色字重补偿。

## 功能

| 能力 | 说明 |
| --- | --- |
| 哈希去重 | 源端与目标端同内容文件只比对哈希，不重复传输；二次备份近乎零写入（规划阶段仍需读取源端内容，见下方判定链路） |
| 改名同步 | 源端 `a.txt` → `doc/a.txt` / `a1.txt` 时，目标端直接改名对齐路径，零字节传输 |
| 内容更新 | 同路径但大小/哈希变化的文件覆盖更新 |
| 多线程复制 | `worker_threads` 复制池，默认 `CPU-1` 并发，上限 8 |
| 断点续传 | 复制中断后按 1 MiB 分片续传，逐片比对目标 `.part` 与源文件的 SHA-256，**只重写损坏、截断或缺失的分片** |
| 拔盘恢复 | 目标介质掉线即停止写入并保全断点；介质回来后**不自动续传**，需用户确认并重新扫描 |
| 同步语义可切换 | 运行时切换 `严格镜像` / `镜像并保留历史`（删除前归档到 `.backup-studio/history`） |
| 删除风险闸门 | 源端为空或孤儿占比过高时强制二次确认，防止误选目录造成不可逆丢失 |
| 逻辑健康检测 | 只读汇聚卷状态、NTFS 脏位、MBR/GPT 校验、备份索引与逐文件哈希；权限不足时明确标注「能力缺失」，不伪造健康结论 |
| 统一写入闸门 | 手动备份与自动同步共用同一个闸门：介质不可达、隔离、L2、磁盘只读、卷需修复、卷健康无法判定，一律拒绝写入 |
| 人工修复入口 | 只读预检 → 选卷 → 两次确认 → 免责 → 先镜像关键扇区 → 生成审计；**只演练不执行修复**，分区表只导出证据 |
| 跨平台能力矩阵 | 3 平台 × 3 接口 × 8 文件系统共 72 组，标注可检测 / 可自动处理 / 仅告警 / 不支持 |
| 自动备份（实时单向同步） | 带开关的单向同步：差异对账 + 事件监听，删除走独立回收站（≥7 天、容量上限）；写入许可由容灾闸门裁决 |
| 重复文件检测与清理 | 标题栏独立入口进入全屏检测页：选任意目录递归检测，**三级判定**（大小分桶 → 首尾 64 KiB 局部哈希 → 全量 SHA-256），结果分列为「内容重复」与「同名不同内容（整页告警、默认不预选）」两个区；逐条「保留 / 删除 / 下次不提醒」、组级「保留此份，其余可删」；删除**只进系统回收站**（不可用时降级本机隔离区、可还原），执行前二次校验（哈希 + 大小 + 文件身份）；「下次不提醒」走内容哈希黑名单，撤销入口是检测页顶部「抑制清单 (N)」；删除复用统一写入闸门并与备份/自动同步互斥，每组至少保留一份 |
| 虚拟列表 | 界面计划清单预览上限 20000 条，虚拟滚动渲染，十万级文件不打爆 IPC；**预览截断不影响后台执行**，全量动作照常跑完 |
| 失败不伪装成功 | 任一文件动作失败、规划期哈希读取失败或清单写入失败时，状态置为「失败」并保留断点与 `.part` 分片，**绝不报完成** |
| 误删防护 | 孤儿文件哈希读取失败、或源端同尺寸文件读取失败时，该孤儿**不生成删除动作**；大小写不敏感文件系统上仅大小写变化的文件不单独删除 |
| 空目录同步 | 源端新增的空目录结构同步到目标端；源端同名 `.backup-studio` 用户目录**不再被跳过** |
| 目录边界校验 | 源目录与目标目录同路径、或互为父子嵌套时直接拒绝，避免递归备份与镜像删除互相冲突 |
| 复制线程自愈 | worker 崩溃或异常退出时终止旧线程、回调当前任务失败并重建槽位，避免池任务永久挂起 |

### 去重与改名判定链路

计划器（`electron/engine/planner.ts`）按五轮收敛，尽量少算哈希。**以下是代码里真实存在的判定顺序**：

1. **零 I/O 快判** —— 只比对**大小**：同路径大小不一致 → 直接判「更新」，不读任何内容；源端存在而目标端缺失 → 判「新增」。
2. **按 size 分桶** —— 源端新增文件先按文件大小分桶，只对「可能与目标端孤儿文件配对」的桶算哈希，避免对全部新文件做哈希。
3. **源端哈希必算** —— 同尺寸文件**必须实算源端 SHA-256**。绝不能用 manifest 里的历史哈希冒充源端当前哈希，否则同尺寸原地改动会被漏备份。
4. **目标端哈希** —— 仅当目标端的 `size` 与 `mtime` **同时**与 manifest 记录吻合时，才复用 manifest 中的历史哈希；否则实算目标端哈希。
5. **改名配对** —— 同哈希且旧路径在目标端成为孤儿 → 判为「改名」；同名优先于改名。

**代价与边界（不要误读为「元数据快判」）**：

- manifest 记录的是**提交后目标端文件**的元数据（`size` / `mtimeMs` / `sha256`），**没有独立的源端元数据基线**。因此**每次规划都会完整读取源端的同尺寸文件**——这是「不漏备份」的正确性代价，不是性能疏忽。
- 「二次备份近乎零写入」指的是**不重复传输**，**不等于零读取**。
- 目标端内容被外部改写、且 `size` 与 `mtime` 均被刻意保留时，默认规划**不会**发现（目标端哈希来自 manifest 缓存）；需要强校验时必须走全量重算路径。

### 执行顺序与提交语义

计划落地严格按 **改名 → 补建目录 → 复制/更新 → 等待全部落盘 → 删除/归档** 的顺序：

- **删除阶段必须排在全部复制彻底落盘之后**。Windows 与 macOS 默认文件系统大小写不敏感，若删除与拷贝并发或交叠，延后执行的 `unlink` 会抹掉刚复制好的新文件。
- 任何一步都要实时响应介质掉线与用户取消，掉线即停止后续写入。
- 部分失败（动作失败 / 规划期哈希读取失败 / 清单写入失败）时状态置为「失败」，**保留 `.part` 分片与活动断点指针**，不清理临时目录，下次运行按分片继续。
- `.part` 临时文件名用相对路径的 SHA-256 前 24 位十六进制（96 bit）作后缀，替代早期 32 位滚动哈希——后者在数万文件规模下会出现命名碰撞，进而导致分片互相覆盖。

### 断点续传如何只重传受损分片

worker 以 1 MiB 为一块遍历源文件，对每一块计算 SHA-256，并与目标 `.part` 对应位置的块逐一比对：

- 目标端该块存在且哈希一致 → **复用，不写入**
- 哈希不一致（等长损坏、写入未落盘）或目标端缺失/截断 → **只重写这一块**

写完后仍回读整份文件重算 SHA-256 与源比对，**校验通过才原子 rename 提交**。校验失败返回 `VERIFY_FAILED` 并保留临时件——不再整份重传，下次运行继续按分片比对。

### 拔盘恢复如何成立

账本（journal）写在**本机 userData**——介质被拔出时续传进度仍然可读，这是恢复的前提；同时尽力双写一份到目标盘并附 CRC32，仅作候选证据。介质可用性以目标根可达性为准而非单一错误码（文件级 `ENOENT` 也可能是介质掉线的表象）。

介质回来后**不会自动续传**：掉线前的计划里含有当时算出的删除动作，直接沿用会误删。因此旧计划立即失效，须由用户确认后重新扫描生成新计划，再按分片续传。

介质掉线后不会再往目标路径写入，也不会重建目标目录：

- 账本镜像双写只在**介质在线、目标根可达、身份未漂移**时进行，且镜像写入**不会创建**目标端目录
- 提交产物时**先 rename 再按需补建目录**，补建之前先复核目标根是否仍可达——不可达即判定掉线，不动目标盘
- 介质回来时校验身份：同一路径插入了**另一块设备**判为身份漂移，禁止写入，不当作「介质恢复」

## 技术栈与选型

**Electron + React + TypeScript + 纯手写 CSS / Design Token**，不引组件库。

选 Electron 而非 Tauri/Rust 的理由：

- 备份是**磁盘 I/O 密集**而非 CPU 密集。哈希走 `node:crypto`（原生 C++ 实现），复制用 `worker_threads` 真并行，与 Rust 版差距极小。
- 本机无 Rust 工具链，安装需额外授权。
- 同一代码库可产出 Windows NSIS `.exe` 与 Linux AppImage / `.deb`，双平台交付成本最低。

界面全部铁律下沉到 CSS 物理层（双环焦点、Grid `0fr→1fr` 折叠、inset 发丝描边），组件库会稀释对这些细节的控制力。

`npm.cmd run test` 一次跑完八套用例（共 265 项，其中 1 项在 Windows 上按环境跳过）：

### 引擎测试 `npm.cmd run test:engine`

覆盖 **54** 个场景（1–42 为通用场景，43–54 为哈希判定与改名配对专项）：

**基础备份与同步**

1. 首次复制全部写入
2. 二次备份哈希命中全部跳过
3. 改名同步（源端改名 → 目标端跟随）
4. 同路径内容更新
5. 严格镜像模式删除源端已消失文件
6. 保留历史模式归档而非删除

**续传与并发**

7. 断点续传后文件字节与全量一致
8. B3：显式恢复只重写损坏、截断和缺失的分片
9. 多线程并发复制结果正确

**掉盘容灾**

10. 拔盘检测：备份过程中目标介质掉线，介质状态转为 lost
11. 掉线后不再向目标盘写入，也不会重建目标目录
12. 只读探测不创建任何目录（探测阶段不得有写副作用）
13. 不存在的路径探测为不可达且不抛异常
14. 介质身份可识别且同一路径比对稳定
15. 介质身份漂移判定为 L2 并禁止写入
16. 不可达介质判定为 L2
17. 证据不足时默认 L1 只读，不自动写盘
18. 隔离状态下即使介质正常也判为 L2
19. 事务日志可检测盘上副本被截断（CRC 不匹配）
20. CRC32 对相同内容稳定且对改动敏感
21. 本机账本在介质不可用时仍可读出断点
22. 隔离标记可撤销，撤销后允许重新备份
23. 中断后旧计划失效，必须重新扫描才能开始

**闸门**

24. 高风险删除触发二次确认闸门

**逻辑健康检测与人工修复（FR-06 / FR-09 / FR-11 / FR-15 / FR-16）**

25. FR-06：真实样本回放，卷告警与脏位优先，SMART 不伪造
26. FR-06：探测不修改目标或本机账本，校验备份索引
27. FR-06：只读校验 MBR 签名及条目边界
28. FR-06：GPT 验证主备头及分区条目 CRC32
29. FR-09：没有二次确认不启动只读预检、镜像或修复
30. FR-09：审计请求后先生成镜像，结果无修复命令

## 已知限制

- Linux 二进制需在 Linux 上构建，或使用仓库内的 GitHub Actions 矩阵产出；本机无 Linux 交叉环境，`release.yml` 尚未实际执行验证。
- **自动备份目前只在 Windows 可用**：卷级健康检查依赖 `Get-Volume` / `fsutil`，Linux 与 macOS 无对应能力，按「不确定时默认只读、不得自动写盘」拒绝写入。手动备份不受此限制。
- **卷需人工检查时全部写入路径都被阻断**：卷处于 `Full Repair Needed` 或 NTFS 脏位时，手动备份与自动备份都会拒写，需先由人工在系统层处理再重新对账。
- `worker_threads` 受 Electron 单进程架构限制，无法通过多进程进一步提升并行度；瓶颈通常在磁盘而非线程数。
- 目标介质为网络盘 / SMB 时，续传需回读并逐块哈希 `.part`，会放大网络往返开销。
- 渲染层 mock 后端仅供浏览器预览界面，不参与真实备份。
- 真实 Electron 原生窗口尚未取证，界面证据仍取自渲染层浏览器。
- 诊断包导出、审计日志、备用介质切换、多配对调度尚未实现。
- **重复文件查找的目标端冗余回收尚未实现**：当前只识别并报告目标端既有冗余副本，不清理它们——目标端是用户的恢复点，回收需要先证明「另有内容完全相同且校验通过的副本」并经逐项授权。详见 `docs/REQUIREMENTS-003-DUPLICATE-FINDER.md` §11 待确认项 #1。
- **回收站列表不做全量内容校验**：回收站上限可达 10 GiB，打开界面时对全部归档算哈希不可接受。列表只比对**大小**并标注有无哈希基线；**还原时严格校验**（有基线则内容不符即拒绝并保留证据），恢复对账与索引重建时校验哈希、不过即转「需人工核对」。因此「登记后被外部篡改且大小相同」的条目在列表上可能仍显示为正常，直到点击还原才会被拒。这是有意的性能取舍。
- **删除阶段会再读一次目标文件**：为保证「删掉的一定在归档里」，删除流程是「用已打开的文件句柄核对内容 → 原子移走到同目录的随机临时名 → 再用句柄核对一次那份实体 → 确认路径仍指向刚校验过的那个实体 → 才真正删除」。移走用的是目标同目录下的临时名（同文件系统内 `rename` 是原子的），临时名**不拼接原文件名**并先落盘到账本，崩溃后能按账本找回；移走的那一份若与归档基线不符，会**原样放回且绝不覆盖**原路径上已有的文件并转「需人工核对」，而不是删掉一份从未被归档的内容。代价是每个被删文件多一到两次全量读取。
- **删除仍有残余窗口**：同一 inode 的原地写入若恰好落在「最后一次身份复核」与真正删除之间，纯 Node 没有「按内容删除」的内核原语可以彻底消除，该窗口已被压到最小但**未完全关闭**，代码注释里如实写明。
- **长文件名的归档副本仍存不下**：待删临时名已不再拼接原 basename（长文件名可以正常删除），但 `transaction.ts` 的归档临时名 `${dest}.tmp-${uuid}` 仍会拼接，basename ≳ 215 字符时归档副本本身超出文件系统单段名上限。本轮未改，见 `docs/TODO.md`。
- **路径身份比较在盘未接入时会退化**：目标端目录读不到（盘未接入 / 权限不足）时，路径同一性退回按平台大小写规则比较，可能把两个真实不同的目标目录判成同一个。两侧都能解析时按磁盘真实身份（`realpath`）判定。
